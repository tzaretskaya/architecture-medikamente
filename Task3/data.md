| Категория        |                                                                                               Примеры данных                                                                                                |                                                                                                   Профиль риска |                                                                                                                                                                                                    Необходимость защиты (CIA) |
|:-----------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|----------------------------------------------------------------------------------------------------------------:|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|
| Критические      |         <ul><li>Медицинская история болезни, диагнозы, результаты обследований</li><li>Персональные данные (ФИО, паспорт, адрес, тел., СНИЛС, полис)</li><li>Данные о согласиях пациентов</li></ul>         |               Высокий. Изменение данных угрожает жизни пациента. <br/>A: Высокая (доступность). Данные должны быть доступны врачу для лечения. |
| Конфиденциальные | <ul><li>Журналы записей к врачам (расписание)</li><li>Финансовые операции, чеки (связка "услуга-стоимость")</li><li>Данные о поставщиках, закупочные цены</li><li>Реестры анализов из лаборатории</li></ul> | Средний. Доступ должен быть ограничен по принципу служебной необходимости. <br/>I: Высокая. Фальсификация записей ведет к финансовым махинациям. <br/>A: Средняя. |
| Публичные        |                      <ul><li>Открытая информация о клинике (услуги, врачи)</li><li>Агрегированные, обезличенные данные для аналитики (например, "средний возраст пациентов")</li></ul>                      |                                                                                                         Низкий. |                                                                                         C: Низкая. <br/>I: Средняя. Искажение публичной информации вредит репутации. <br/>A: Высокая. Сайт и информация должны быть доступны. |

## 2. Защита Данных в Разных Состояниях (Data-at-Rest, Data-in-Transit, Data-in-Use)

| Состояние данных               |                                          Угрозы                                          |                                                                                                                                                                                          Базовые инструменты защиты (все данные) |                                                                                                                                                                                                                                                                                                                                              Продвинутые инструменты (для критических данных) |
|:-------------------------------|:----------------------------------------------------------------------------------------:|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|
| Data-at-Rest (При хранении)    |         Кража носителей, несанкционированный доступ к файлам/БД, утечка бэкапов.         |                                       1. Шифрование дисков (Full Disk Encryption): - BitLocker (Windows Server), LUKS (Linux) для серверов и рабочих станций.<br/>2. Контроль доступа: - RBAC/ABAC через Privacy Service и СУБД. |                                                                                                                                                            Шифрование на уровне приложения/поля: - Шифрование критичных полей (диагноз, ФИО) с использованием ключей, хранящихся в Hardware Security Module (HSM) или Azure Key Vault / AWS KMS. Даже при компрометации БД данные недоступны. |
| Data-in-Transit (При передаче) |                      Перехват трафика (MitM-атака), подмена данных.                      | 1. Сквозное шифрование (TLS 1.2+): - Для всего веб-трафика (HTTPS). - Для API-вызовов между сервисами. <br/>2. VPN: - Для безопасного подключения удаленных сотрудников и филиалов (например, по протоколу IPsec или WireGuard). |                                                                                                                                                                                                                 Аутентификация сертификатов: - Взаимная аутентификация (mTLS) для критичных сервисов (например, c Laboratory), чтобы гарантировать, что данные передаются доверенной системе. |
| Data-in-Use (При обработке)    | Утечка через оперативную память, доступ к данным у привилегированных администраторов БД. |      1. Маскирование данных в интерфейсах: - Для сотрудников ресепшена отображать только часть номера телефона (+7 XXX XXX-XX-XX).<br/>2. Сегрегация обязанностей: - Администратор БД не должен быть администратором приложения. | 1. Конфиденциальные вычисления (Confidential Computing): - Обработка данных в защищенных, изолированных областях памяти (Enclaves, например, Intel SGX). Даже администратор облака не может увидеть данные в памяти. <br/>2. Псевдонимизация в Analytical Data Warehouse: - Данные для аналитики автоматически очищаются от прямых идентификаторов, что сводит риск при обработке к минимуму. |

## 3. Автоматизированный Контроль и Мониторинг

| Категория контроля                            |                                                                                                                                                        Инструменты и методы                                                                                                                                                         |
|:----------------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|
| Обнаружение и классификация данных            |                                                                                                                               Collibra: Автоматически сканирует источники данных и классифицирует их.                                                                                                                               | 
| Мониторинг и предотвращение утечек (DLP)      |               Data Loss Prevention (DLP) системы: - Сетевой DLP: Контроль исходящего трафика (блокировка отправки медкарт на личную почту). - Endpoint DLP: Контроль на рабочих станциях (запрет копирования на USB). - Cloud DLP (для Analytical Platform): Мониторинг запросов на выгрузку больших объемов данных.                | 
| Расширенный аудит и реагирование на инциденты | Security Information and Event Management (SIEM): - Splunk, Elastic SIEM, ArcSight. - Агрегирует логи со всех систем: Privacy Service (попытки доступа), БД (запросы к критичным таблицам), файловых серверов. Строит "картину атаки" и автоматически alerts при подозрительной активности (сотрудник ночью скачивает 100 медкарт). | 
| Управление доступом                           |                                                                                               Привилегированный доступ (PAM): - CyberArk, Thycotic. Контроль и мониторинг сессий администраторов к критичным системам (БД, сервера).                                                                                                | 

## 4. Реестр Программных и Аппаратных Средств Защиты Данных

| Категория                              |                             Назначение                             |                                                                                                                                                      Примеры инструментов / решений |
|:---------------------------------------|:------------------------------------------------------------------:|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|
| Шифрование и управление ключами        | Защита данных при хранении и управление криптографическими ключами |          - Аппаратный HSM (Thales, SafeNet) / Облачные KMS (Azure Key Vault, AWS KMS) - СУБД с TDE (Microsoft SQL Server, Oracle Database) - Системное шифрование (BitLocker, LUKS) |
| Защита передачи данных                 |    Обеспечение конфиденциальности и целостности данных в сети.     |                         - Сертификаты TLS/SSL (от Let's Encrypt или коммерческих CA) - VPN-шлюзы (Cisco ASA, FortiGate, OpenVPN) - Средства mTLS (встроено в frameworks приложений) |
| Контроль доступа и идентификация       |        Аутентификация и авторизация пользователей и систем.        | - Privacy & Consent Management Service (как PDP/PIP) - Сервисы каталогов (Active Directory, Azure AD) - Многофакторная аутентификация (MFA) (Duo Security, Microsoft Authenticator) |
| Защита от утечек и мониторинг          |   Обнаружение, классификация данных и реагирование на инциденты.   |                    - Системы DLP (Symantec DLP, Microsoft Purview DLP) - SIEM-системы (Splunk Enterprise, Elastic Stack, QRadar) - Системы классификации данных (Microsoft Purview) |
| Безопасность приложений и данных       |                 Защита на уровне приложений и БД.                  |                                     - Маскирование и псевдонимизация данных (кастомная логика в ETL Orchestrator и Privacy Service) - Сканеры уязвимостей (для веб-приложений и БД) |
| Резервное копирование и восстановление |                  Обеспечение доступности данных.                   |                                                                                                                      - Инструменты бэкапа (Veeam, Commvault) с шифрованием архивов. |
